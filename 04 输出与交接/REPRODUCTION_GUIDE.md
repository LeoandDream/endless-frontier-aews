# 完成与快速复现规范

> AEWS v0.2.0 · Normative Specification

## 1. 目的

下游 Execution Agent 的成功任务必须留下足够的 Reproduction Information，使用户或未来 Agent 能在合理范围内重现结果，而不是只知道最终文件被修改过。Generator 的 Artifact 只规定复现要求，不表示已完成复现。

## 2. 最小复现信息

- AEWS 版本和任务版本；
- 代码或文档版本、Commit 或工作区状态；
- 操作系统、运行时、关键依赖和硬件；
- 输入文件、数据集、配置、权重和环境变量的位置；
- 执行命令、参数和工作目录；
- 预期输出和实际输出位置；
- 验证命令、结果和通过标准；
- 需要人工观察的步骤；
- 已知不可复现因素或随机性。

## 3. 复现步骤

~~~text
准备环境
→ 获取正确版本
→ 准备输入和配置
→ 执行命令
→ 检查输出
→ 运行验证
→ 对比预期结果
~~~

每一步都应具有实际路径、命令或清晰操作说明；不能只写“按之前步骤运行”。

## 4. 复现失败

复现失败时不要修改历史成功结论。记录失败环境、差异、日志和可能原因，使用 UNVERIFIED 或 BLOCKED，并生成续接材料。

## 5. 快速复现与完整复现

快速复现用于验证主要结果；完整复现还应包含数据版本、环境安装、配置生成、随机种子、完整日志和所有依赖。交付时说明当前提供的是哪一种。
