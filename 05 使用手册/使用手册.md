# AEWS 使用手册

> AEWS v0.2.0 · User Guide

## 1. AEWS 默认帮我做什么？

你只需要说想完成什么。AEWS 默认不会替你直接完成目标项目任务，而是把需求收敛为另一个 Agent 可以可靠执行的指令制品。

默认产物：

- 单次任务：`TASK_PROMPT.md`；
- 长期项目规范：目标项目 `AGENTS.md`；
- 恢复中断工作：`CONTINUE_PROMPT.md`。

你不需要学习 Prompt Engineering，也不需要主动说“生成 Prompt”。

## 2. 什么请求会生成 Prompt？

默认所有普通请求都会生成适用的 Artifact，包括简单知识问题、调研、分析、编码、Debug、实验和集成。

例如：

- “robosuite 支持哪些机器人？” → 简洁 Research / Answer Prompt；
- “调研目前 CCF-A 会有哪些发表的 VLA 综述。” → Research Prompt；
- “我如何将 NERO 接入 robosuite？” → Engineering Prompt；
- “分析 VLA 失败恢复是否值得研究。” → Analysis / Research Prompt。

简单任务的 Prompt 更短，但不会因为简单而被跳过。

## 3. 什么时候直接回答或直接执行？

明确说出覆盖语句即可：

- “你直接回答，不要生成 Prompt。”
- “这次不用给另一个 Agent。”
- “直接分析即可，不走 AEWS Prompt 构建。”
- “当前 Agent 直接执行。”

若要求当前 Agent 直接执行，它会明确从 Generator 切换为 Execution Agent；随后会检查目标项目、执行、验证和交付。默认行为仍是先生成 Artifact。

## 4. AEWS 会调查什么？

AEWS 会调查生成可靠指令所必需的最小上下文，例如已提供资料、Reference Index、必要官方文档、已知路径和任务边界。

如果完整仓库扫描、文献调研、实验或代码调查本身就是你的目标，AEWS 会把这些工作写入下游 Prompt，而不会先替未来 Agent 完成一次。相关资料在 Workspace 中也不等于自动属于当前任务。

## 5. 为什么会问我问题？

AEWS 只会询问会改变 Goal、Scope、Artifact 类型、关键架构/接口、数据、模型、实验设计、验收或重要取舍的材料性问题。它会先调查可可靠获得的信息，再说明不确定点、影响、选项和推荐。

局部命名、文件组织、等价工具选择等非材料性事项会写入下游 Agent 的 L0/L1 决策边界，而不是频繁打断你。

## 6. 我如何获得长期项目 AGENTS.md？

例如说：

> 为我的 robosuite + NERO 实验项目建立 Agent 开发、验证和交付规范。

AEWS 会生成可放进目标项目根目录的 `AGENTS.md`。该文件约束未来进入目标项目的 Execution Agent，与 AEWS 自己的 `AGENTS.md` 不同。

如果还要安排首个工作任务，请一并说明；AEWS 会在确有需要时同时提供项目 `AGENTS.md` 和首个 `TASK_PROMPT.md`。

## 7. 我如何继续中断任务？

提供已有的检查点、日志、错误、已完成工作或 Continuation Guide，并说“生成续接 Prompt”。AEWS 会输出 `CONTINUE_PROMPT.md`，让下一个 Execution Agent 知道当前状态、不要重复的尝试、恢复条件、下一步和验证要求。

## 8. 我会看到什么阶段？

Generator 可能显示：

- `AEWS · Requirement Draft`
- `AEWS · Context Acquisition`
- `AEWS · Awaiting Decision`
- `AEWS · Requirement READY`
- `AEWS · ARTIFACT_READY`

这些只说明 AEWS 正在生成指令，不代表下游项目已经执行、验证或完成。

## 9. 如何理解完成？

`ARTIFACT_READY`：AEWS 已生成可靠的指令制品。

`COMPLETED`：下游 Execution Agent 已在目标环境中通过所有强制验收、验证、Evidence、复现和交付门槛。

二者不能互换。Prompt 已生成不等于代码已实现、研究已完成或实验已验证。

## 10. 资料和项目边界

AEWS 的 Reference Materials 只保存资料索引、路径和 URL。真实项目的当前代码、配置、测试、数据、设备和 Git 状态属于 Target Project Context，需要下游 Agent 在真实环境中检查。
