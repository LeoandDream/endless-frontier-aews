# 案例 B：复杂工程任务

## 用户请求

“把这个组件正式接入现有系统，要求保留旧接口并支持新配置。”

## Generator 初始判断

这是 Engineering `TASK_PROMPT.md`。Generator 不直接接入目标项目；“正式接入”的边界可能涉及公共接口、配置格式、兼容性和验收范围，必须收敛为下游 Agent 的明确任务约束。

## Generator 必要上下文

Generator 只在可可靠访问且生成 Prompt 所必需时检查：

- 组件当前是否存在及其入口；
- 现有调用方和公共 API；
- 配置加载方式和版本兼容；
- 测试、部署入口和文档；
- 当前实际接入状态；
- 用户已经确认的兼容性要求。

## Material Unknown

如果项目资料无法确定“正式接入”是否包括部署、性能、监控或迁移，Codex 批量提出 L2 问题，说明每个选择对接口、数据、运维和验收的影响。

## Task Tree

只有有独立验收的部分才拆分：

- CRITICAL：保留旧接口并接入新路径；
- REQUIRED：完成配置兼容和错误处理；
- REQUIRED：补充集成验证；
- OPTIONAL：更新额外示例文档。

## Artifact 与下游执行

Requirement READY 后，Generator 自动生成 `TASK_PROMPT.md` 并进入 `ARTIFACT_READY`，明确 Goal、Scope、Out of Scope、User Decisions、Context to Inspect、Acceptance Criteria 和验证。下游 Execution Agent 接收 Prompt 后进入 Inspect → Understand → Plan → Execute → Verify。

## 结果

如果下游集成测试通过但性能和用户验收未完成，状态只能是 UNVERIFIED 或 AWAITING_USER，不能宣布 COMPLETED。若服务器不可用，状态为 BLOCKED 并生成 Continuation Guide / CONTINUE_PROMPT。Generator 不能将 Artifact 生成写成这些下游结果。
