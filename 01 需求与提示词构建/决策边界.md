# 决策边界

> AEWS v0.2.0 · Normative Specification

## 1. 目的

Decision Boundary 用于明确 **Generator 可以决定什么**、**用户必须决定什么**，以及 Generator 应当如何把未来 Execution Agent 的决策和授权规则写入 Artifact。它不把 Generator 与目标项目的 Execution Agent 混为同一角色。

## 2. Generator Decision Boundary

Generator 可以自主：

- 检查当前用户消息、AEWS Reference Index、已提供文件和可靠公开资料；
- 选择 Artifact 的组织方式和最小必要章节；
- 依据已确认项目惯例表达非材料性实现建议；
- 把下游的 Inspect、Research、Plan、Execute、Verify、Delivery 规则写入 Artifact；
- 在资料不足时把需要目标环境检查的事项列为 Target Project Context。

Generator 必须询问用户：

- 用户希望的 Goal、Scope、Deliverable、Acceptance 或验证语义存在材料性歧义；
- Artifact 类型本身（单次任务、长期项目治理、续接）会改变用户获得的产品；
- 用户必须选择的重要架构、接口、数据、模型、实验或长期取舍无法从可靠来源确定。

Generator 不得自行：

- 以“未来 Agent 会实现”为由改变用户 Goal 或缩小验收；
- 把 `INFERRED + MATERIAL` 写成 User Decision；
- 替目标项目用户授予未来的 L3 高风险授权；
- 因 Reference Context 可访问而扩大 Target Project Scope。

## 3. Execution Decision Boundary（写入 Artifact）

每个适用的 `TASK_PROMPT.md` 或目标项目 `AGENTS.md` 必须向下游 Agent 给出以下边界：

### L0 — Autonomous

低风险、局部、可逆且不改变项目语义的事项，例如读取文件、搜索项目、检查 Git、诊断环境、遵循已有命名和等价内部拆分。

### L1 — Autonomous + Record

存在多个合理方案，但不改变 Goal、公共 API、架构、数据语义或重要项目方向。Execution Agent 可以选择并记录依据、影响和替代方案。

### L2 — User Decision

影响架构、公共接口、数据格式、依赖路线、模型、控制策略、实验设计、未来扩展、重要性能、可靠性或维护性取舍时，Execution Agent MUST 停止并向用户说明：不确定点、影响、可选方案及推荐理由。

### L3 — Explicit Authorization

大规模删除或覆盖数据、删除数据集或 checkpoint、`git reset --hard`、force push、生产环境修改、破坏性数据库操作、安全敏感修改或大型依赖升级，需要目标项目用户针对具体操作明确授权。

## 4. 判断流程

~~~text
发现未知、选择或操作
    ↓
它是否改变 Generator 要生成的 Goal / Scope / Artifact / Acceptance？
    ├─ 是 → Generator 调查或 Ask User
    └─ 否
它是否属于 Target Project Context，需由 Execution Agent 在真实环境判断？
    ├─ 是 → 写入 Artifact 的 Inspect / Stop / Decision Boundary
    └─ 否
是否为 L0 / L1 惯例性事项？
    ├─ 是 → Generator 可表达为自主约束
    └─ 否 → 列为 L2 或 L3 下游规则
~~~

## 5. 澄清问题格式

Generator 的 L2 问题应采用：

```text
需要你决定：[具体任务语义或 Artifact 选择]

原因：该选择会影响[Goal / Scope / Architecture / API / Data / Experiment / Acceptance]。

选项：
- A：[方案与主要影响]
- B：[方案与主要影响]

推荐：[可选推荐]，因为[可靠事实或取舍理由]。
```

不得用“你想怎么做？”替代边界说明。彼此独立的问题应批量提出。

## 6. 决策记录要求

Generator 记录的每个材料性决定至少包括：主题、角色（Generator / Execution）、权限级别、证据、用户选择或下游 Stop Rule、影响范围，以及是否改变 Artifact 的 Scope、Acceptance 或 Verification。

已经由用户解决的决定不得无新证据反复询问。下游执行期未解决的 L2/L3 规则必须保留在 Artifact 中，不可在 Generator 阶段伪装为已解决。

## 7. Context Boundary

`AEWS REFERENCE CONTEXT` 帮助 Generator 生成 Artifact；`TARGET PROJECT CONTEXT` 是 Execution Agent 必须在真实环境检查的对象；`UNRELATED WORKSPACE CONTENT` 不得因同属一个 Workspace 就被自动读取或纳入 Scope。

## 8. 一致性规则

- Decision Boundary 不得降低用户原始需求或验收语义。
- AEWS `AGENTS.md` 只约束 Generator；目标项目 `AGENTS.md` 才约束 Execution Agent。
- Generator 的资料调查与 Execution Agent 的项目 Inspect 必须清楚分开。
- 能可靠获得的生成所需事实不得升级为用户问题；需要目标项目现场证据的事实不得伪装成 Generator 已验证事实。
- L3 安全授权与 L2 项目决策必须分开记录。
